# Security: OAuth2 client-credentials custody, secret management, and supply-chain hardening

> **왜 중요한가** — CLAUDE.md secret rules; ADR-0001 single token place; ADR-0011/0015 App-key-never-local; env.example TOSS_CLIENT_SECRET; go.mod toolchain pinned for govulncheck zero reachable stdlib vulns; #72 secret scanner promoted to CI gate; #76/#87 scanner trust boundary and push-protection posture; configs/gate risk classification; modernc.org/sqlite dependency. Need current best practice to finish #87 and to harden the deployment host.

수집 방식: 학술·공식/표준·업계/포스트모템·한국어 4경로 병렬 검색 → 종합·공백 판정(최대 2라운드 재수집). 출처 23건. 상태 집계: 🟡 부분 9, ✅ 답변됨 2

## 핵심 결론

- **GitHub Actions supply-chain hardening: SHA-pinning actions, least-privilege GITHUB_TOKEN permissions, environment-scoped secrets (loop-pr), OIDC instead of long-lived PATs, Dependabot/renovate for actions, the 2025 tj-actions/changed-files compromise lessons.** — Best practice per GitHub: pin actions by full SHA because tags are mutable; default GITHUB_TOKEN to read and elevate per job; never check out PR code under pull_request_target and use workflow_run for privilege separation; pass untrusted input through env vars; prefer OIDC; gate environment secrets with required reviewers [gh-docs-actions-secure-use]. tj-actions (CVE-2025-30066) showed that retroactively moved tags could dump runner memory secrets for more than 23,000 repositories on 2025-03-14 and 15, so every reachable secret had to be rotated [ghsa-tj-actions-changed-files-cve-2025-30066]. Repo state: every action is SHA-pinned, top-level permissions are contents: read, and pr-creation runs only on repository_dispatch with an App token [repo-workflows][repo-adr-0011]. Gap: there is no dependabot.yml, and Dependabot alerts skip SHA-referenced actions, so only version-update PRs keep pins fresh [gh-docs-actions-secure-use]. OIDC has nothing to replace today, because there is no cloud deploy and the App installation token is already short-lived.
- **Go supply chain: govulncheck in CI (reachability), go.sum/GOFLAGS=-mod=mod pitfalls, GOPROXY/GONOSUMDB, toolchain pinning semantics (toolchain go1.26.5 directive), SBOM generation (syft, cyclonedx-gomod), SLSA provenance via goreleaser/slsa-github-generator, reproducible builds.** — Toolchain: the go line is a hard minimum, while the toolchain line is only a suggestion used when it is newer than the default. GOTOOLCHAIN=local ignores it; auto downloads it and verifies it via sumdb, not go.sum; GOSUMDB=off breaks the download [go-doc-toolchain]. setup-go's go-version-file prefers the toolchain directive (main-branch README; confirm for the pinned v5.6.0) [actions-setup-go-readme][repo-workflows]. govulncheck source mode uses the Go on PATH as build configuration, so the toolchain decides which stdlib vulnerabilities are reported. It reports reachable symbols only. Text mode exits non-zero on findings, while -json, sarif and openvex exit 0 regardless [govulncheck-pkgdev]. CI correctly uses text mode, but pins govulncheck v1.6.0 while pkg.go.dev already showed v1.9.0 as not the latest [repo-workflows][govulncheck-pkgdev]. SBOM: cyclonedx-gomod app mode, matching the build env, with -noserial and -notimestamp [cyclonedx-gomod]; sqlite ships its own SBOMs [modernc-sqlite-pkgdev]. Provenance: slsa-github-generator is unmaintained [slsa-github-generator-readme], so use actions/attest (attest-build-provenance v4 wraps it), which works on public repos on every plan but needs GHEC on private repos [attest-build-provenance-readme]. GOFLAGS=-mod=mod pitfalls and reproducible-build docs were not verified.

## 질문별 답변

### T10.Q1 · OAuth 2.0 client-credentials best practice (RFC 6749 §4.4, RFC 6819 threat model, OAuth 2.1 draft, RFC 9700 security BCP): secret storage, rotation cadence, never logging tokens, token binding, and what to do when the provider offers no revoke endpoint.

🟡 부분 · 우선순위 must · 확신 low

No OAuth RFC text was verified: rfc-editor.org and datatracker.ietf.org were unreachable and the search budget was exhausted. Verified project facts: Toss is client-credentials only, with a 24 h token, no refresh token and one valid token per client, and a re-issue invalidates the previous token [repo-adr-0001]. Re-issue is therefore the only token-revocation lever. The client_secret itself can only be killed by rotating it with Toss; this is inferred, not checked against Toss docs. Never-log and redaction are handled by config.Secret [repo-go-mod-config]. For storage, file-based encrypted credentials (LoadCredentialEncrypted) beat environment variables: they are not inherited by children, are readable only by the service user and sit in unswappable memory [systemd-credentials-doc][systemd-exec-man-source]. SetCredential= must never carry the secret [systemd-exec-man-source]. Unverified recall: RFC 9700 prefers sender-constrained tokens (mTLS/DPoP) and asymmetric client authentication. Toss appears to offer only a form-body secret, so compensating controls are an IP allowlist (if Toss offers one, unverified), the kill switch and alerting.

### T10.Q2 · Secret injection options for a single-VM Go daemon: systemd LoadCredential/credstore, sops+age, HashiCorp Vault/OpenBao agent, AWS/GCP secret managers, commercial secret-manager connectors — tradeoffs for unattended restart without human unlock.

🟡 부분 · 우선순위 must · 확신 medium

systemd credentials are the verified best fit for unattended restart on a single VM. LoadCredentialEncrypted decrypts at service start with a key bound to the TPM2 and/or /var/lib/systemd/credential.secret. No human unlock is needed, and a stolen ciphertext is useless on another host [systemd-credentials-doc][systemd-exec-man-source]. Credentials appear in a read-only $CREDENTIALS_DIRECTORY, readable only by the service user, not inherited by children, held in unswappable memory and limited to 1 MB per unit. Pitfalls: --with-key=null gives no confidentiality, kernel-cmdline credentials are world-readable, and SetCredential= must not hold secrets [systemd-credentials-doc][systemd-exec-man-source]. sops+age needs an age identity file on disk for unattended decryption. ssh-agent is unsupported, and YubiKey or passphrase identities need a human [age-readme]. On a single VM that is weaker than TPM sealing. OpenBao offers dynamic credentials and lease revocation, but it is a whole service, and its agent auto-auth was not verified [openbao-readme]. Toss secrets are static, so dynamic credentials do not apply. The AWS/GCP managers and commercial secret-manager connectors were not verified. Reasoned tradeoff: each of them moves the root of trust to a machine identity and adds an availability dependency at boot.

### T10.Q3 · Host hardening for a trading VM: minimal image/distroless, non-root user, read-only FS except data dir, egress allowlist to openapi.tossinvest.com, static egress IP for the Toss IP allowlist, automatic OS patching vs stability, SSH hardening.

🟡 부분 · 우선순위 must · 확신 medium

Verified building blocks: (1) modernc.org/sqlite is pure Go, so a CGO_ENABLED=0 static binary works on a minimal or distroless image [modernc-sqlite-pkgdev]. (2) ProtectSystem=strict makes the whole filesystem read-only except /dev, /proc and /sys. Pair it with PrivateDevices=, ProtectKernelTunables= and ProtectControlGroups=, and open only the store and audit data directory with ReadWritePaths= [systemd-exec-man-source]; ReadWritePaths= itself was not read. (3) A dedicated user plus encrypted credentials keeps the secret out of plaintext on disk and out of child environments [systemd-credentials-doc]. (4) tj-actions was detected by egress monitoring, which supports an egress allowlist [ghsa-tj-actions-changed-files-cve-2025-30066]. Not verified: IPAddressAllow/IPAddressDeny syntax (these work on IPs, not hostnames, so a DNS-name allowlist needs a proxy or nftables), whether Toss has an IP allowlist (and so needs a static egress IP), unattended-upgrades reboot policy, and CIS SSH baselines.

### T10.Q6 · Secret scanning posture (#87): GitHub push protection and secret scanning for custom patterns, gitleaks/trufflehog in CI as signal vs gate, allowlist pinning, pre-commit hooks — and the trust boundary of running a scanner from a PR checkout (ADR-0011 4(a)/(b)).

🟡 부분 · 우선순위 must · 확신 medium

Trust boundary: scan.sh runs from the PR checkout and resolves its allowlist there, so a PR controls its own allowlist. ADR-0011 point 7 already makes such output untrusted, and #87's signal-not-gate framing is correct [repo-issue-87][repo-adr-0011][repo-workflows]. Gitleaks has the same pitfall. Its config precedence ends at .gitleaks.toml in the target, and inline gitleaks:allow is honoured unless --ignore-gitleaks-allow is passed. Pin it with --config pointing at a base-ref copy, and pin the pre-commit rev, noting that SKIP=gitleaks bypasses the hook [gitleaks-readme]. TruffleHog verified results are high-signal (--fail exits 183), but verification makes outbound provider calls, which widens CI egress [trufflehog-readme]. On a public repo exposure happens at push time, so only push protection prevents it, and push protection is currently disabled [repo-issue-87][repo-adr-0015-0016]. A gating variant must run base-defined code under workflow_run without checking out PR code [gh-docs-actions-secure-use]. The availability of push protection and custom patterns on user-owned public repos, and the security_and_analysis API, are not verified.

### T10.Q7 · Threat model for the bot: stolen client_secret (attacker can trade), compromised dependency (modernc.org/sqlite, x/sys), malicious PR via loop (prompt injection), host compromise — STRIDE/attack-tree write-ups for trading bots and mitigations (IP allowlist, account-level limits, alerts on unknown orders).

🟡 부분 · 우선순위 should · 확신 low

No external STRIDE or attack-tree write-up for trading bots was found. Evidence-backed elements follow. (1) CI dependency compromise: tj-actions exfiltrated every reachable secret [ghsa-tj-actions-changed-files-cve-2025-30066]. Mitigations here are SHA pins and confining the App key to the loop-pr environment [repo-workflows][repo-adr-0011]. (2) Go dependency compromise: a single direct dependency with a fragile libc lockstep [modernc-sqlite-pkgdev][repo-go-mod-config]. govulncheck finds known CVEs only, not malicious code [govulncheck-pkgdev]. (3) Malicious loop PR or prompt injection: ADR-0011 4(e) treats PR text as untrusted, with fail-closed verdicts [repo-adr-0011]. (4) Stolen client_secret: the attacker can trade. Two issuers would keep invalidating each other's tokens [repo-adr-0001], so a 401 burst is a detection signal. TPM sealing defeats exfiltration from disks and backups but not live host compromise [systemd-credentials-doc]. (5) Host compromise: root can read $CREDENTIALS_DIRECTORY and process memory, and runtime/secret does not change that [go-runtime-secret-pkgdev]. Toss IP allowlists, account limits and unknown-order alerts are unverified.

### T10.Q8 · Token-in-one-place enforcement: ensuring only one process holds credentials (systemd single instance, file permissions 0600, no secrets in env for child processes, memory zeroing limits in Go).

🟡 부분 · 우선순위 should · 확신 medium

systemd credentials give: readable only by the unit user, not passed to children, hidden from other services, unswappable memory [systemd-credentials-doc][systemd-exec-man-source]. The repo instead reads TOSS_CLIENT_SECRET from the environment [repo-go-mod-config], which children inherit [systemd-credentials-doc]. No single-instance lock exists, despite ADR-0001's single-issuer rule [repo-go-mod-config][repo-adr-0001]. Memory zeroing: runtime/secret was implemented for Go 1.26 [go-issue-21865-runtime-secret], but it is experimental. It needs GOEXPERIMENT=runtimesecret, is outside the Go 1 compatibility promise, only works on linux/amd64 and arm64, does not protect globals, and erases heap memory only after references are dropped and the GC runs [go-runtime-secret-pkgdev]. The secret also passes through net/http form encoding and header strings, so zeroing reduces exposure at most and must not be claimed as a guarantee.

### T10.Q9 · Audit of GitHub App permissions and fine-grained PAT scopes for the loop identity (ADR-0011 point 5 narrowing, verify-credential-narrowing.sh): minimal scopes for repository_dispatch, PR creation, check runs; what admin bypass vectors remain (ADR-0016 vector (d)).

🟡 부분 · 우선순위 should · 확신 low

Repo, verified: the admin token is a master key; enforce_admins does not block edits to protection; narrowing is a Phase B precondition; enforce_admins=false during bootstrap [repo-adr-0011][repo-adr-0015-0016]. pr-creation.yml needs no GITHUB_TOKEN write scopes [repo-workflows]. GitHub guidance: least privilege per job and required reviewers on environment secrets [gh-docs-actions-secure-use]. tj-actions shows that any secret in a job running third-party actions is exposed if one action is compromised, so the loop-pr job should run as few actions as possible [ghsa-tj-actions-changed-files-cve-2025-30066]. Not verified: per-endpoint App and fine-grained PAT permissions (recall says repository_dispatch needs Contents: write; verify this before verify-credential-narrowing.sh hard-codes it) and ruleset bypass actors vs classic enforce_admins.

### T10.Q10 · Dependency policy for OSS-quality repo: license scanning, pinned versions, minimal deps (currently only modernc.org/sqlite), vendoring vs module proxy, and CVE monitoring (OSV, GitHub advisories) for Go.

🟡 부분 · 우선순위 nice · 확신 medium

License: sqlite is BSD-3-Clause, bundling public-domain SQLite and MIT sqlite-vec [modernc-sqlite-pkgdev]. cyclonedx-gomod reports license evidence at 0.85 confidence by default, and mod mode suits license and vulnerability monitoring [cyclonedx-gomod]. Pinning: the repo pins v1.53.0 against upstream v1.61.1, and libc must move in lockstep [modernc-sqlite-pkgdev][repo-go-mod-config]. CVE monitoring: govulncheck reachability in CI [govulncheck-pkgdev]; there is no Dependabot gomod config [repo-workflows]. Vendoring: SBOMs from vendored modules have no hashes [cyclonedx-gomod], so the module proxy plus sumdb remains the default. OSV-Scanner and go-licenses were not verified.

### T10.Q11 · Backup/escrow of secrets and disaster recovery for a solo operator (lost laptop, lost 2FA) without weakening the 'human-only initial authorization' gate (ADR-0007).

🟡 부분 · 우선순위 nice · 확신 low

Credentials bound to the TPM or host key decrypt only on the original hardware and install [systemd-credentials-doc]. Losing the VM therefore means re-provisioning: rotate the Toss client_secret, re-seal it on the new host, and boot halted until a human authorizes (ADR-0007). This keeps the human-only gate intact. An offline escrow copy could be age-encrypted to a hardware or passphrase identity, since those need a human by design [age-readme]. That fits break-glass, which should never be unattended. An exposed App key stays valid until rotated [repo-adr-0015-0016]. GitHub 2FA recovery practice was not verified.

## 프로젝트 함의

- go.mod `toolchain go1.26.5` is not an enforced floor. GOTOOLCHAIN=local or a newer local Go bypasses it [go-doc-toolchain]. govulncheck source mode reports against whatever Go is on PATH [govulncheck-pkgdev], so CLAUDE.md's 'govulncheck floor' holds only in CI. Fix: set GOTOOLCHAIN=go1.26.5 in build and unit scripts, or have CI assert `go version`. Never set GOSUMDB=off.
- CI pins govulncheck@v1.6.0, but pkg.go.dev already lists v1.9.0 as not the latest [govulncheck-pkgdev][repo-workflows]. Bump it through Dependabot or a reviewed PR. Keep text mode, and add an enforcement test that the ci.yml govulncheck line has no -json or -format flag (under the gate promotion rule this is sacred).
- #87: gitleaks and TruffleHog share scan.sh's flaw that config and allowlists come from the PR checkout [gitleaks-readme]. If #87 adopts one, pass --config pointing at a base-ref copy plus --ignore-gitleaks-allow, or keep it as a signal per ADR-0011 point 7. TruffleHog verification adds outbound egress from CI [trufflehog-readme]. The only push-time prevention is enabling push protection, and the #87 posture checker should fail closed when it is off [repo-issue-87].
- Add .github/dependabot.yml (github-actions and gomod). Alerts ignore SHA-pinned actions [gh-docs-actions-secure-use]. It is a sacred .github/ path, so it must land before W0 (ADR-0016 point 5). ADR-0011's PR-author invariant must say whether dependabot[bot] PRs are allowed outside the mechanu[bot] dispatch path.
- modernc.org/sqlite v1.53.0 trails v1.61.1, and libc must move in lockstep [modernc-sqlite-pkgdev][repo-go-mod-config]. Treat the bump as a risk:high store PR (ADR-0005) gated on go test -race.
- ADR-0001's single issuer is not mechanized, since no lock exists [repo-go-mod-config]. A follow-on ADR should add a systemd single unit plus an exclusive lock on the store directory, so that a second instance halts instead of invalidating the token.
- Propose an ADR so config.Load reads $CREDENTIALS_DIRECTORY/toss_client_secret (LoadCredentialEncrypted, TPM2-bound) ahead of the environment, keeping env for dev only [systemd-credentials-doc][systemd-exec-man-source]. The unit runs with ProtectSystem=strict, ReadWritePaths covering only the data directory, and a dedicated user. Unattended restart works with no unlock, and ADR-0007 first-boot halt is unaffected. This is a risk:high TDD change (precedence and redaction tests).
- Do not claim zeroization in ADRs. runtime/secret is experimental: it needs GOEXPERIMENT=runtimesecret, works only on linux/amd64 and arm64, and is outside the Go 1 promise [go-runtime-secret-pkgdev]. A GOEXPERIMENT build flag would also change the build configuration govulncheck analyses. Defer it.
- Provenance: skip slsa-github-generator, which is unmaintained [slsa-github-generator-readme]. Use actions/attest plus a cyclonedx-gomod SBOM with -noserial and -notimestamp [attest-build-provenance-readme][cyclonedx-gomod]. Attestations work on a public repo on every plan, but need GHEC if the repo goes back to private. Any provenance workflow used as a deploy gate must be registered as sacred.
- Stolen-secret runbook: a re-issue kills only the token [repo-adr-0001]. Respond with a global halt, rotate the secret at Toss, re-seal it with systemd-creds and have a human re-authorize. Wire a sustained 401 pattern as a kill-switch trigger (ADR-0004/0012).

## 출처 간 상충

- CLAUDE.md says the repo is private, while issue #87 records it as public [repo-issue-87]. This changes which features apply: push protection and attestations are free on public repos, but attestations need GHEC on private ones [attest-build-provenance-readme]. Resolve it by live-checking repo visibility before #87 and any provenance work.
- ADR-0011 records enforce_admins=true (2026-07-08 snapshot), while the ADR-0016 live measurement (2026-07-23) shows false. The true value was stale; false is the bootstrap value, and true is the target.
- Issue #76 assumed push protection was active; #87 and ADR-0016 measured it as disabled. Trust the live measurement.
- An earlier synthesis said 'Go 1.26 ships runtime/secret' [go-issue-21865-runtime-secret], but the package docs say it is experimental and gated behind GOEXPERIMENT [go-runtime-secret-pkgdev]. The package docs are authoritative.
- GitHub recommends SHA pinning, but slsa-github-generator requires an @vX.Y.Z tag [gh-docs-actions-secure-use][slsa-github-generator-readme]. Moot, because the generator is unmaintained; use actions/attest.
- SHA pinning vs Dependabot alerts, which cover only semver-referenced actions [gh-docs-actions-secure-use]. Keep SHA pins and rely on version-update PRs.
- CLAUDE.md and go.mod call toolchain go1.26.5 a 'floor', but the Go docs define the toolchain line as a non-binding suggestion [go-doc-toolchain]. It is a floor only under GOTOOLCHAIN=auto or setup-go; enforce it explicitly elsewhere.

### 출처 요약

- **`ghsa-tj-actions-changed-files-cve-2025-30066`** — Official advisory for the March 2025 tj-actions/changed-files compromise; four pool copies merged into this entry. The attacker retroactively repointed existing version tags to a malicious commit. That commit dumped Runner Worker memory secrets, base64-encoded, into workflow logs. It is the primary evidence that tag pinning does not protect, that SHA pinning does, and that any secret reachable during the exposure window must be rotated. It also shows that egress monitoring caught the attack. _(접근: open access)_
- **`gh-docs-actions-secure-use`** — Source of GitHub's official Actions hardening guide. It covers SHA pinning, least-privilege GITHUB_TOKEN, the dangers of pull_request_target, script injection, OIDC, environment required reviewers and Dependabot coverage of actions. _(접근: open access via the github.com source repo (docs.github.com does not resolve from this session))_
- **`systemd-credentials-doc`** — Upstream design document for systemd service credentials. LoadCredentialEncrypted is TPM2- and/or host-key-bound and decrypts unattended at service start. Credentials are exposed only to the service user, are not inherited by child processes and are held in non-swappable memory. _(접근: open access)_
- **`systemd-exec-man-source`** — Upstream XML source of systemd.exec(5), read only in part. It verifies the ProtectSystem=strict semantics, the LoadCredential/LoadCredentialEncrypted behaviour and $CREDENTIALS_DIRECTORY, and warns that SetCredential= must not carry secrets. ReadWritePaths= and IPAddressAllow= were not read. _(접근: open access (raw XML, very large; partially read))_
- **`go-doc-toolchain`** — Source of the official Go toolchain document. It defines go-line and toolchain-line semantics, GOTOOLCHAIN modes and toolchain verification. _(접근: open access via github.com)_
- **`actions-setup-go-readme`** — README for the action the repo uses with go-version-file: go.mod. It says the toolchain directive takes precedence when present. This is the main-branch README; the repo pins v5.6.0. _(접근: open access; main branch may differ from the pinned v5.6.0)_
- **`govulncheck-pkgdev`** — Official govulncheck reference; two pool copies merged. It covers source and binary modes, reachability, exit-code semantics and output formats. One pool fetched v1.9.0, which the page marked as not the latest, while CI installs v1.6.0. _(접근: open access)_
- **`go-runtime-secret-pkgdev`** — Official documentation for runtime/secret; two pool copies merged. secret.Do erases registers and stack, and erases heap memory once the GC finds it unreachable. The package is experimental: it needs GOEXPERIMENT=runtimesecret and only protects on linux/amd64 and linux/arm64. _(접근: open access; experimental)_
- **`go-issue-21865-runtime-secret`** — Tracking issue for runtime/secret. It was closed as completed with commit a3fb92a on 2025-11-26 under the Go1.26 milestone. It records why a GC runtime cannot guarantee erasure in general. _(접근: open access)_
- **`gitleaks-readme`** — Primary gitleaks documentation; two pool copies merged. It covers allowlists, baselines, inline suppression and config precedence. A scan of a PR checkout picks up config the PR supplies unless --config is pinned. The project is feature complete and only receives security patches. _(접근: open access)_
- **`trufflehog-readme`** — Primary TruffleHog documentation; two pool copies merged. It covers verified, unverified and unknown result statuses, PR diff scanning, the --fail exit code and pre-commit use. Verification makes outbound calls to the provider. _(접근: open access)_
- **`attest-build-provenance-readme`** — GitHub's action for signed SLSA build provenance attestations. Since v4 it is a wrapper over actions/attest. It is the maintained successor path to slsa-github-generator. _(접근: open access)_
- **`slsa-github-generator-readme`** — SLSA L3 provenance generator; the root README and the Go-builder README entries were merged. It is no longer actively maintained (last release v2.1.0, February 2025) and recommends GitHub artifact attestations instead. It must be referenced by tag, not by SHA. _(접근: open access; Go builder README at /blob/main/internal/builders/go/README.md)_
- **`cyclonedx-gomod`** — Go-specific CycloneDX SBOM generator with app, mod and bin modes, reproducibility flags and license evidence. _(접근: open access)_
- **`age-readme`** — age file-encryption tool and format, the usual sops backend. Unattended decryption needs an identity file on disk, because ssh-agent is not supported and hardware or passphrase identities need a human present. _(접근: open access)_
- **`openbao-readme`** — MPL-2.0 fork of Vault offering encrypted storage, dynamic credentials and lease revocation. The page did not cover agent auto-auth. _(접근: open access)_
- **`modernc-sqlite-pkgdev`** — Package page for the repo's only direct dependency. It is a pure-Go (no cgo) port under BSD-3-Clause that ships SBOMs. It requires go.mod to pin the same modernc.org/libc version that sqlite uses. _(접근: open access)_
- **`repo-adr-0001`** — Project ADR. Toss is client-credentials only, issues an 86400 s token with no refresh token, and allows one valid token per client, so a re-issue invalidates the previous token. Token issuance is confined to a single process. _(접근: repo-internal)_
- **`repo-adr-0011`** — Project ADR. The App key and token exist only in the loop-pr environment. It separates unprivileged pull_request jobs (4(a)) from privileged base-defined jobs (4(b)), treats PR text as untrusted (4(e)), and makes unprivileged output a non-trusted gate input (point 7). _(접근: repo-internal)_
- **`repo-adr-0015-0016`** — Project ADRs. They forbid local materialization of the App key, record enforce_admins=false as the bootstrap value, define the W0 window, and record secret scanning and push protection as disabled. _(접근: repo-internal)_
- **`repo-workflows`** — Current CI and loop workflows. All actions are SHA-pinned and top-level permissions are contents: read. pr-creation runs only on repository_dispatch and uses an App token. govulncheck@v1.6.0 runs in text mode. scan.sh runs from the PR checkout. There is no dependabot.yml. _(접근: repo-internal)_
- **`repo-issue-87`** — Open issue that reframes the CI scan as a signal, not a gate, closes the relative-path allowlist hole and adds a push-protection posture checker. It records the repo as public with secret scanning and push protection disabled. _(접근: repo-internal)_
- **`repo-go-mod-config`** — go 1.25.0 with toolchain go1.26.5 as the stdlib vulnerability floor, and modernc.org/sqlite v1.53.0 (libc v1.73.4, x/sys v0.44.0). TOSS_CLIENT_SECRET is read only through os.Getenv into config.Secret. No single-instance lock exists. _(접근: repo-internal)_
