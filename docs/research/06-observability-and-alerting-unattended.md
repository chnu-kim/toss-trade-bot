# Observability for unattended systems: structured logs, durable audit, alerting, dead-man switches, SRE practice

## 질문별 답변

### T6.Q1 · Which alerting channels are viable for a solo operator in Korea with delivery guarantees and acknowledgement (Telegram bot, Slack webhook, Discord, email, SMS via Twilio/NHN Cloud, Kakao 알림톡, PagerDuty/Opsgenie free tiers, ntfy, Pushover) — latency, cost, rate limits, outage history, and API auth model?

🟡 부분 · 우선순위 must · 확신 medium

Pushover is the only consumer channel found with acknowledgement built in. An emergency-priority message re-notifies every `retry` seconds until acknowledged or `expire`. It returns a receipt that can be polled or paired with a callback, and it can be cancelled by receipt or tag [pushover-receipts-api]. The Telegram Bot API has no acknowledgement. Its limits are about 1 msg/s per chat with 429 on sustained overage, and 20 msg/min in groups [telegram-bots-faq], which is ample for one private chat if alerts are deduplicated. ntfy is a plain HTTP POST with priority 1 to 5. It can be self-hosted, has no ack or escalation, and the public server returns 429 per visitor [ntfy-publish-docs]. Kakao 알림톡 requires a dealer contract, a business-verified channel and template review, so it is effectively out of reach for an individual [bizgo-alimtalk-guide]. SMS via NHN Cloud or Twilio, the PagerDuty and Opsgenie free tiers, Slack and Discord webhooks, latency, pricing and outage history all remain unverified (only low-credibility third-party figures were found, and they were dropped).

### T6.Q2 · Dead-man switch / heartbeat monitoring services (Healthchecks.io, Cronitor, Dead Man's Snitch, Grafana OnCall, UptimeRobot) — how to signal 'bot alive AND reconciler healthy AND not halted' and alert on silence.

🟡 부분 · 우선순위 must · 확신 medium

Healthchecks.io alerts when no ping arrives within period plus grace. /start, /fail and /<exitcode> signal start and explicit failure, so a failure alerts without waiting for silence [healthchecks-docs]. It is open source and self-hostable [healthchecks-docs]. Cronitor works the same way (GET/POST/HEAD, ?state=fail), but a monitor stays silent until its first ping [cronitor-heartbeat]. Dead Man's Snitch has one snitch on the free plan [deadmanssnitch-faq]. Recommended signal: a supervised goroutine sends success only when all of these hold: the process is up, killswitch CanSubmit, the reconciler made progress within the window (no ADR-0014 escalation) and the last audit segment commit succeeded. It sends /fail when halted, and sends nothing otherwise. Then 'dead', 'halted' and 'stuck' all page [healthchecks-docs]. Pre-create the check rather than auto-provisioning it, because of the first-ping pitfall [cronitor-heartbeat]. Grafana OnCall and UptimeRobot are unsourced.

### T6.Q3 · Alert design for money-moving systems: severity taxonomy (halt tripped, ambiguous backlog, token refresh failing, reconciler stuck, disk nearly full), alert deduplication/escalation, and avoiding alert fatigue (Google SRE 'Monitoring Distributed Systems', 'My Philosophy on Alerting').

🟡 부분 · 우선순위 must · 확신 medium

Page only on urgent, actionable, symptom-level conditions. Cause alerts are allowed only for imminent cliffs such as disk or quota, and an alert that needs only a robotic response should not page [sre-book-monitoring][ewaschuk-alerting-philosophy]. A person can sustain only a few urgent pages a day [ewaschuk-alerting-philosophy]. Knight Capital is the money-moving precedent: 97 automated pre-open emails flagged the fault, but they were not designed as alerts and were not reviewed [sec-knight-34-70694][wilmerhale-knight]. Proposed taxonomy (derived): PAGE with ack (Pushover emergency [pushover-receipts-api]) for global halt tripped, dead-man silence or /fail, reconciler escalation or ambiguous backlog, token refresh failing (it trips halt per ADR-0004), and audit local write failure. PAGE as a cause alert for audit disk above threshold [sre-book-monitoring]. TICKET or digest for long remote-shipping lag and repeated 429s. Deduplicate by keeping one active emergency per halt episode, with tag-based cancel when a person clears the halt [pushover-receipts-api]. The escalation chain beyond one person is not applicable to a solo operator.

### T6.Q4 · Structured logging best practice in Go (log/slog handlers, attribute conventions, correlation ids per intent/orderId, redaction of secrets, sampling) and log shipping/rotation options for a single VM (journald, vector, promtail/Loki).

🟡 부분 · 우선순위 should · 확신 medium

Use ReplaceAttr as a last-line scrubber over all non-group attributes, LogValuer placeholders for secret types, and With or WithGroup for per-intent and per-orderId correlation. JSONHandler does one Write per record, which suits line shippers. Handle errors are swallowed [go-log-slog-pkgdoc]. Scrubbers must also handle a LogValuer that resolves to a Group [go-slog-handler-guide]. The stdlib has no sampler; samber/slog-sampling exists, but halts and audit events must bypass sampling [samber-slog-sampling]. On a single VM: journald bounded by SystemMaxUse/SystemKeepFree [systemd-journald-conf], then shipping via Alloy loki.source.journal, which silently collects nothing without the adm and systemd-journal groups [alloy-loki-source-journal], or via Vector with a bounded disk buffer [vector-buffering-model].

### T6.Q5 · Audit trail requirements for trading records: what regulators expect to be retained (order, modification, cancel, execution timestamps; MiFID RTS 25 clock sync as reference; KR 주문기록 보존 의무) and the retention period — to size ADR-0006 segments and the remote shipping target.

🟡 부분 · 우선순위 should · 확신 low

EU reference only: order and transaction data are retained for 5 years (MiFIR Art. 25), with content defined by RTS 24 [mifir-art25-records]. Clocks are UTC-traceable within 100 µs, 1 ms or 1 s by activity tier, documented and reviewed annually [eu-2017-574-rts25]. Neither binds a Korean retail self-trader. The Korean obligations (자본시장법 시행령 and 금융투자업규정 order-record retention) were not found, and that duty most likely falls on the broker (unverified). Practical sizing (inference): plan for 5 years of audit segments in remote storage, and record UTC wall-clock timestamps from an NTP-synced host plus monotonic durations.

### T6.Q6 · Remote audit shipping designs (ADR-0006 point 5): at-least-once shippers to S3/object storage with idempotent keys, local backlog bounds, and how to verify shipped completeness (manifests, checksums) without gating prune.

🟡 부분 · 우선순위 should · 확신 medium

Ship each immutable segment from ADR-0006 point 4 with PutObject using If-None-Match: *, keyed by segment name, so a retry that gets 412 means already shipped [aws-s3-conditional-writes]. Send x-amz-checksum-sha256 (base64) so S3 rejects corrupt uploads [aws-s3-checksums]. A manifest of segment name and SHA-256, compared periodically with the bucket listing, verifies completeness. That check only feeds a metric or alert and never gates prune, consistent with ADR-0006 points 4 and 5. If a generic shipper is used, a bounded disk buffer with when_full=block is the lossless option. Note that Vector exits on buffer-disk exhaustion [vector-buffering-model]. For segments under 5 GB, single-part PUT avoids the multipart checksum ambiguity [aws-s3-checksums]. Non-AWS object stores (R2, B2, GCS) were not checked for If-None-Match support.

### T6.Q7 · Metrics for a trading bot: what to export (orders submitted/rejected, fills, latency to ack, ambiguous count, halt state, PnL, exposure, API quota usage) and lightweight stacks (Prometheus + Grafana Cloud free tier, OpenTelemetry) suited to one process.

🟡 부분 · 우선순위 should · 확신 medium

Counters: orders submitted, rejected and filled, 429s, alert delivery failures. Gauges: halt 0/1, ambiguous backlog, exposure, audit disk bytes, oldest unshipped segment age. Histogram: submit-to-ack latency [prometheus-client-golang-pkgdoc]. Use a custom registry with promhttp.HandlerFor. MustRegister panics, so register only at boot [prometheus-client-golang-pkgdoc]. Golden signals frame which of these are symptoms [sre-book-monitoring]. Grafana Cloud free-tier limits, OpenTelemetry versus client_golang, and push versus pull behind NAT are unsourced.

### T6.Q8 · Daily reconciliation reports and end-of-day statements: comparing bot journal against broker-provided trade confirmations/statements (Toss app exports), and alerting on drift.

❌ 미답 · 우선순위 should · 확신 low

No source on Toss execution-history endpoints, statement export formats or end-of-day reconciliation practice was reachable. Repo-based inference: ADR-0003 makes GET /api/v1/orders/{orderId} the source of truth, so a daily job could diff that day's terminal audit records against broker order and execution history, and raise a ticket-level alert on any break (escalating to a page if exposure differs).

### T6.Q9 · Notifier reliability itself: what if the alert channel is down during a halt — fallbacks, local durable alert queue, and 'alert delivery failure' treated as an incident (relation to ADR-0004 notifier seam).

🟡 부분 · 우선순위 should · 확신 medium

Knight shows that a notification path nobody watches is the same as no alerting [sec-knight-34-70694]. Mechanisms found: Pushover receipts let the sender verify acknowledgement and re-escalate [pushover-receipts-api]. Telegram can return 429 under bursts [telegram-bots-faq]. slog swallows Handler.Handle errors, so today's slogNotifier cannot detect a failed delivery [go-log-slog-pkgdoc]. Design (derived): the Notifier seam (ADR-0004 point 8, non-blocking, under the transition lock) enqueues into a durable local outbox. A supervised drainer sends to the primary channel (an ack-capable one) and falls back to a second channel. Undelivered or unacknowledged past a deadline counts as its own incident, and that state is folded into the dead-man heartbeat as /fail, so an independent service pages when the channel itself is down [healthchecks-docs]. No source covers outbox or always-firing watchdog patterns specifically.

### T6.Q10 · Postmortem culture and runbook practice for solo-operated systems (SRE blameless postmortems, runbook templates), aligned with the repo's docs/runbooks and retro format.

🟡 부분 · 우선순위 nice · 확신 low

The only sourced principles are: pages need human judgement and a clear failure condition, and cause information belongs inside the page or on a dashboard [sre-book-monitoring][ewaschuk-alerting-philosophy]. Both imply each page class needs a runbook link. The SRE postmortem-culture chapter and runbook templates were not retrieved. Repo: docs/runbooks/ holds only governance runbooks, with no operational runbook for halt release, ambiguous backlog or token-refresh failure.

### T6.Q11 · Privacy/secret hygiene in logs and audit: Korean PIPA implications for account identifiers in logs, what to redact (accountSeq? tokens), and OSS-safety of log samples in the repo.

🟡 부분 · 우선순위 nice · 확신 low

Mechanics: LogValuer placeholders plus a ReplaceAttr deny-list for accountSeq, Authorization or bearer values and raw HTTP bodies [go-log-slog-pkgdoc][go-slog-handler-guide]. Heartbeat ping URLs and keys are secrets too [healthchecks-docs]. PIPA status of brokerage account identifiers and the 안전성 확보조치 기준 access-log rules remain unsourced.

## 프로젝트 함의

- ADR-0004 point 8 and its Follow-up '알림 채널 구체화': the evidence favours an ack-capable primary channel (Pushover emergency [pushover-receipts-api]) plus an independent dead-man service [healthchecks-docs] over Telegram, Slack or email alone. Knight [sec-knight-34-70694] shows that notifications without ack or ownership fail. Kakao 알림톡 is impractical for an individual [bizgo-alimtalk-guide].
- The Notifier seam (internal/killswitch/seam.go: non-blocking, under the transition lock, recover-wrapped) means the implementation must be enqueue-only into a durable outbox, with a separate Supervisor-managed drainer. Today's slogNotifier (internal/runtime/app.go) cannot observe delivery failure, because slog discards Handle errors [go-log-slog-pkgdoc].
- Heartbeat content should mirror killswitch, reconciler and audit health, and send /fail on halt [healthchecks-docs]. Global halt is released only by a person (ADR-0004/0012), so a halted bot must not look green. Ping URLs are secrets and should be injected like config.Secret.
- ADR-0006 point 5 (remote shipping undecided) is consistent with S3 If-None-Match write-once keys plus SHA-256 checksums [aws-s3-conditional-writes][aws-s3-checksums]. The immutable segments from point 4 map 1:1 to object keys. A manifest check feeds a metric only and leaves prune gating on the local ack, so the rejected alternative 'ack = 원격 수집기 확인' stays rejected.
- ADR-0006 point 5's 'local audit disk = monitoring target, alert target undecided' is exactly the kind of cause alert SRE permits as a cliff [sre-book-monitoring]. Classify it as a page, while shipping lag is a ticket. If Vector is ever used as the shipper, it exits on buffer-disk exhaustion [vector-buffering-model], which must not take the bot down. Keep the shipper out of process or under Supervisor.
- Segment retention: the only sourced benchmark is the EU's 5 years [mifir-art25-records]. The Korean duty is unknown, so the remote target retention should be a config value, not hard-coded, until the statute is verified.
- internal/runtime.NewLogger (slog.NewJSONHandler with nil options) should gain a ReplaceAttr deny-list for accountSeq and Authorization values, Group-aware per issue 62731 [go-slog-handler-guide]. Never sample halt or audit-relevant lines [samber-slog-sampling].
- Metrics: register at boot in cmd/bot wiring (MustRegister panics) [prometheus-client-golang-pkgdoc], in line with the CLAUDE.md 'never die' rule. Keep clientOrderId and orderId (ADR-0002) out of labels.
- Readiness: Q1 to Q3 now have enough sourced basis to draft a notification ADR via /architect. Q5 (KR retention) and Q8 (Toss statements) still block the final remote-shipping and reconciliation-report designs.

## 출처 간 상충

- slog ReplaceAttr: the pkgdoc says it is never called for Group attrs [go-log-slog-pkgdoc], while issue 62731 says it can receive a Group resolved from a LogValuer [go-slog-handler-guide]. Resolve by writing the scrubber to handle both.
- S3 multipart SHA-256: sources disagree on full-object vs composite support [aws-s3-checksums]. Resolve by using single-part PUT for segments.
- Vector when_full default: block per the official docs [vector-buffering-model], while third parties report it inconsistently. The official docs take precedence.
- journald SystemMaxUse default: 10% of the filesystem (older) vs min(10%, 4G) (newer) [systemd-journald-conf]. Check on the target VM.
- Dead Man's Snitch free-plan hourly interval: contradictory within the FAQ [deadmanssnitch-faq].
- Ewaschuk essay date is given as 2012, 2013 or 2014 across sources [ewaschuk-alerting-philosophy]. This does not affect the content.
- Kakao 알림톡: dealer sources disagree on whether recipients must be channel friends [bizgo-alimtalk-guide].

### 출처 요약

- **`sre-book-monitoring`** — The standard chapter on monitoring: symptoms versus causes, the four golden signals, and what should page a human. It is the basis for a severity taxonomy where halt-tripped is a symptom page and disk-nearly-full is a cause alert, allowed only because it predicts a cliff. Seen only through search excerpts in several passes; the page fetch was blocked by the DNS allowlist. _(접근: open access; claims from search excerpts, not fetched)_
- **`ewaschuk-alerting-philosophy`** — The Google SRE essay that chapter 6 and Prometheus alerting practice build on. Pages must be urgent, actionable, real and symptom-based. A responder can react urgently only a few times a day before fatigue sets in. Cause-based alerts are tolerated sparingly. Seen via search excerpts only. _(접근: open access; not fetched; year varies 2012-2014 across secondary sources)_
- **`sec-knight-34-70694`** — The SEC's settled order under Market Access Rule 15c3-5 over the 2012-08-01 incident, with a $12M penalty. Before the open, an internal system sent 97 automated emails that referenced the router error. They were not designed as alerts and were generally not reviewed. The order also faults reliance on human monitoring of exposure with no automated alerts. This is the money-moving precedent for treating halts as owned pages and not as unread mail. The order PDF was not fetched. The digest https://www.sec.gov/news/digest/2013/dig101613.htm covers the same order. _(접근: open access; press release/digest seen via search; order text not fetched)_
- **`wilmerhale-knight`** — A law-firm summary that backs up the SEC order's observability findings: the warning emails were not reviewed, and there were no automated exposure alerts. _(접근: open access; search excerpt)_
- **`pushover-receipts-api`** — Emergency-priority messages repeat until the user acknowledges them or they expire. The send call returns a receipt that can be polled or paired with a callback, and retries can be cancelled by receipt or by tag. Among the channels researched, it is the only consumer one with built-in acknowledgement and retry-until-ack, which fits a halt page for a solo operator. Seen via search excerpts in three independent passes. _(접근: open access; fetch blocked; minimum retry value and pricing not verified)_
- **`telegram-bots-faq`** — Telegram's official guidance on bot flood limits. One private chat carrying halt alerts sits far below the limits, but a burst of alerts must be deduplicated to avoid 429s. Bot API sends have no acknowledgement or escalation semantics. Seen via search excerpts in four passes. _(접근: open access; fetch blocked; figures from excerpts)_
- **`ntfy-publish-docs`** — An open-source, self-hostable HTTP pub-sub push service. Publishing is a plain HTTP POST or PUT, with priority 1 to 5 set by header. It has no native acknowledgement or escalation. The public ntfy.sh server rate-limits per visitor with HTTP 429; the exact figures are unverified. _(접근: open access; fetch blocked)_
- **`bizgo-alimtalk-guide`** — A dealer's guide to Kakao Alimtalk, not Kakao policy. Sending requires an official Kakao dealer, a business-verified Kakao channel (business registration) and Kakao-reviewed templates, and is limited to informational messages. That is impractical for an individual operator. The companion page is https://blog.bizgo.io/howto/alimtalk-guide/. _(접근: Korean-only; secondary (dealer) source)_
- **`healthchecks-docs`** — A dead-man-switch service that is also open source and self-hostable. Each check has a period and a grace time. Silence past period plus grace raises an alert. The /start, /fail and /<exitcode> suffixes signal job start and explicit failure. An explicit /fail alerts immediately, without waiting for silence. This maps directly onto the composite 'alive AND reconciler healthy AND not halted' heartbeat. The run-time page is https://www.healthchecks.io/docs/measuring_script_run_time/. _(접근: open access; fetch blocked; free-tier limits not verified)_
- **`cronitor-heartbeat`** — Commercial heartbeat monitors. A ping is any GET, POST or HEAD to the telemetry URL, and ?state=fail reports an explicit failure. A monitor stays silent until its first ping, which is a pitfall: a bot that never starts never alerts. _(접근: open access; search excerpt)_
- **`deadmanssnitch-faq`** — FAQ of a long-running dead-man-switch service. The free plan has one snitch. The FAQ contradicts itself on whether hourly intervals are free. Useful only as a comparison point. _(접근: open access; excerpt only)_
- **`go-log-slog-pkgdoc`** — The official reference for Go structured logging. This is the only source fetched in full (the first 100k characters). It covers ReplaceAttr, LogValuer redaction, With and WithGroup, and JSONHandler's single-write-per-record behaviour. It applies directly to internal/runtime.NewLogger and config.Secret. _(접근: open access; fetched)_
- **`go-slog-handler-guide`** — The Go team's handler-writing guide (this URL is a commit view) says custom handlers should offer ReplaceAttr. Together with issue 62731 it shows a subtlety: an attr whose value comes from a LogValuer can resolve to a Group, which affects scrubber design. _(접근: open access; commit-view URL)_
- **`samber-slog-sampling`** — Third-party slog sampling middleware with uniform, threshold, absolute and custom strategies, MIT licensed. Sampling may apply to repetitive diagnostics only. Halts and audit-relevant events must bypass it. _(접근: open access)_
- **`systemd-journald-conf`** — Size and retention limits for journald on a single VM. This is an old (buster) version, so defaults may differ on the target. The freedesktop upstream page is the canonical text. _(접근: open access; versioned mirror)_
- **`alloy-loki-source-journal`** — The Alloy component (Promtail's successor) that ships the systemd journal to Loki. It has a silent-failure pitfall that matters to the observability invariant: missing group membership collects nothing and raises no error. _(접근: open access)_
- **`vector-buffering-model`** — Memory and disk buffers, and the when_full policy (block, drop_newest, overflow). The lossless choice is a bounded disk buffer with block. Vector exits if it cannot write the disk buffer. Both points matter to a bounded local audit backlog. The Rust docs (rust-doc.vector.dev) duplicate this and add a 500 ms disk sync interval. _(접근: open access; search excerpt)_
- **`aws-s3-conditional-writes`** — A PutObject or CompleteMultipartUpload with If-None-Match: * succeeds only if the key does not exist. That gives at-least-once shippers write-once segment keys: a retry that gets 412 means the segment is already shipped. A bucket policy can enforce the header. _(접근: open access)_
- **`aws-s3-checksums`** — S3 additional checksums (CRC32/CRC32C/CRC64NVME/SHA-1/SHA-256) are verified server-side on upload, so a mismatch is rejected. This is the basis for a per-segment SHA-256 manifest to verify shipped completeness without gating prune. _(접근: open access)_
- **`prometheus-client-golang-pkgdoc`** — The official Go instrumentation client, partly fetched in a prior pass. It defines Counter, Gauge, Histogram and *Vec, custom registries and promhttp. It is the minimal in-process metrics surface for one process. _(접근: open access; partially fetched)_
- **`mifir-art25-records`** — The source of the EU five-year retention period for order and transaction data. RTS 24 (2017/580) specifies content only. A reference standard for sizing retention, not binding in Korea. _(접근: open access; search excerpt)_
- **`eu-2017-574-rts25`** — The MiFID II standard on UTC traceability of business clocks for reportable events. It is a reference for audit timestamp discipline only (NTP-synced UTC wall clock plus a monotonic clock for durations), not binding on a Korean retail bot. A revision moves the requirements to MiFIR Art. 22c. _(접근: open access; search excerpts)_
